# Data Model: Mach 4 Transition & State Evaluation

**Feature**: Evaluate Current State for Mach 4 Transition
**Date**: 2026-10-04

---

## 1. Evaluation & Diagnostic Entities

### `EvaluationSession`
Represents an execution of the state evaluation suite.
- **`session_id`** (`string`, UUID): Unique identifier for the audit session.
- **`timestamp`** (`datetime`): Timestamp of evaluation execution.
- **`target_branch`** (`string`): Active Git branch evaluated.
- **`lifecycle_target`** (`enum`: `MACH2`, `MACH3`, `MACH4`): Current target milestone (`MACH4`).
- **`overall_status`** (`enum`: `PASS`, `WARN`, `CRITICAL_FAIL`): Aggregate readiness health.
- **`dimension_checks`** (`list[SystemDimensionCheck]`): Results across evaluated dimensions.

### `SystemDimensionCheck`
Individual invariant evaluation.
- **`dimension`** (`enum`: `SECURITY_TENANCY`, `DATA_PERSISTENCE`, `PILLAR_BALANCER`, `ML_TOOLS`, `FRONTEND_A11Y`, `DOCUMENTATION`): Evaluated architecture domain.
- **`check_name`** (`string`): Short identifier (e.g., `CHECK_NEO4J_POOLING`, `CHECK_ZERO_TRUST_SECRETS`).
- **`status`** (`enum`: `PASS`, `WARN`, `FAIL`): Result of check.
- **`diagnostic_message`** (`string`): Actionable explanation.
- **`constitutional_principle`** (`string`): Referenced principle (e.g., `Principle I`, `Principle III`).

## 2. Mach 4 Core Life Engine Entities

### `VersionedIntentionChain` (Neo4j Graph Pattern)
Represents fluid daily planning where intentions can evolve throughout the day while preserving audit trails.
- **Node `Day`**: `{date: ISO8601String, user_email: string}`
- **Node `Intention`**:
  - `intention_id`: Composite UUID (`hash(user_email + date + version)`)
  - `version`: Integer (1, 2, 3...)
  - `created_at`: ISO8601 Timestamp
  - `pillar`: String (e.g., "Engineering Core", "Health/Rest", "Admin")
  - `planned_minutes`: Integer
  - `description`: Text
- **Relationship `[:PLANNED_AT]`**: `{sequence: Integer}`
- **Terminal Delta Rule**:
  $$\Delta = \text{Actual} - \text{Intention}_{terminal}$$

### `HeroNumbersDelta` (Analytical Metric)
The quantitative variance between intended time allocation and verified actuals.
- **`user_email`** (`string`): Tenant email.
- **`week_id`** (`string`): ISO week identifier (e.g., `2026-W40`).
- **`pillar_deltas`** (`map[string, float]`): Delta per pillar in hours (positive = surplus, negative = deficit).
- **`valuable_detour_hours`** (`float`): Unplanned time spent on growth/value.
- **`detrimental_detour_hours`** (`float`): Unplanned time spent on avoidance/stagnation.
- **`alignment_score`** (`float`, 0.0 - 1.0): Normalized alignment with `hero_future.json`.

### `BurnoutRiskMetric` (ML Tool Output: Prophet/LSTM)
Output of `get_burnout_risk(user_id)`.
- **`user_email`** (`string`): Tenant identifier.
- **`risk_score`** (`float`, 0.0 - 1.0): Probability of burnout.
- **`risk_level`** (`enum`: `LOW`, `ELEVATED`, `CRITICAL`): Categorical alert tier.
- **`contributing_signals`** (`list[string]`): E.g., `["Sleep gap variance > 2.5h", "Work blocks > 12h consecutive"]`.
- **`recommended_action`** (`string`): E.g., `"Schedule mandatory 4-hour restorative block on Wednesday"`.

### `MilestonePathRecommendation` (ML Tool Output: Reinforcement Learning)
Output of `calculate_path_to_milestone(target)`.
- **`target_milestone`** (`string`): Target goal node (e.g., `"Principal Architect 2028"`).
- **`projected_weeks`** (`int`): Simulated virtual weeks to goal.
- **`success_probability`** (`float`, 0.0 - 1.0): Probability under optimal intention quota.
- **`recommended_weekly_quotas`** (`map[string, int]`): Target hours per pillar needed to stay on trajectory.

### `GrandVisionaryReview` (Tier 3 Echelon Entity)
Monthly macro-review generated by the Grand Visionary agent.
- **`review_month`** (`string`): Format `YYYY-MM`.
- **`derivative_trajectory`** (`float`): Rate of change in life pillar alignment.
- **`ten_year_roadmap_adjustments`** (`list[string]`): Proposed shifts to multi-year milestone graph.
- **`human_ratification_status`** (`enum`: `PENDING_REVIEW`, `APPROVED`, `ADJUSTED`): Human-in-the-loop sign-off status.
